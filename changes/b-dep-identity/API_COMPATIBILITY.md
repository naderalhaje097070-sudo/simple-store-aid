# API compatibility
No financial RPC, data schema, return contract, valid tool argument schema, OAuth audience, billing/provider policy or generated API route changes. MCP POST bodies now have explicit limits:65536 bytes,256 combined array/object members, object/container depth32 and5s read deadline. Oversize/structure413, malformed/aborted400 and read deadline408 contain fixed nonlogging errors. Valid bodies are forwarded byte-for-byte with original headers/signal. Existing real SDK initialize/list/call/invalid-tool/missing-token checks and source-linked server-entry tests are required on final locked source. Non-MCP requests remain the original object.
