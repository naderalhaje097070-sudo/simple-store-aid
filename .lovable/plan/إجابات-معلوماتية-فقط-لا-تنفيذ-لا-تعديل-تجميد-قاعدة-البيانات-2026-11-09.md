# إجابات معلوماتية فقط (لا تنفيذ، لا تعديل، تجميد قاعدة البيانات محترم)

ملاحظة: لم ألمس أي ملف أو قاعدة بيانات. هذه الإجابات من توثيق Lovable، ولم أتحقق من قائمة الترحيلات الحية في هذه الجلسة.

## 1) هل يطبّق Lovable الترحيلات القادمة من GitHub تلقائيًا؟
لا. المزامنة مع GitHub تنقل الملفات فقط ولا تطبّق أي ترحيل على قاعدة البيانات أبدًا. الطريقة المدعومة الوحيدة: أن يُطلب من المساعد داخل المحادثة تطبيقها عبر أداة الترحيل، ثم يوافق المالك على كل ترحيل.
السبب المرجّح لعدم تطبيق التسعة: أُضيفت إلى GitHub (يدويًا أو من أداة أخرى) ولم يطلب أحد تطبيقها من المحادثة.

## 2) الطريقة الآمنة لتطبيقها لاحقًا
- بعد رفع التجميد: يُراجع كل ترحيل من التسعة بالترتيب، ويُتأكد أنه لا يتعارض مع ما طُبّق مباشرة (مثل إصلاح الأمان 20261107214500).
- يُطبّق عبر أداة الترحيل في المحادثة، واحدًا تلو الآخر، بموافقتك، بعد أخذ تصدير احتياطي.
- السجل يبقى متسقًا لأن الأداة نفسها تسجّل كل ترحيل تطبّقه. أما الترحيل المطبّق مباشرة وغير الموجود في GitHub فيجب إضافة ملفه إلى المستودع لاحقًا حتى يتطابق الطرفان. توجد أداة "فحص سجل الترحيلات" تقارن الملفات بالقاعدة دون تغيير شيء.

## 3) الاستعادة من نسخة احتياطية
- نعم، تستبدل القاعدة كاملة في مكانها: البيانات والهيكل والصلاحيات وسجل الترحيلات، كما كانت لحظة النسخة.
- حسابات المستخدمين: جزء من القاعدة، فتعود لحالتها وقتها (من سجّل بعدها يضيع).
- ملفات التخزين: غير مشمولة إطلاقًا ولا تتأثر.
- المدة: القاعدة تتوقف بضع دقائق.
- لا يمكن التراجع عنها. كل ما كُتب بعد النسخة يضيع. نسخة يومية واحدة، لحوالي 14 يومًا، دون استعادة لحظة محددة. الأفضل أخذ تصدير قبل أي استعادة.

## 4) أثناء تعليق حساب GitHub
- التعديلات داخل Lovable محفوظة بأمان؛ المشروع والاستضافة والقاعدة لا تعتمد على GitHub.
- المزامنة تتوقف فعليًا، وما يُعدَّل هنا لن يصل GitHub حتى تعود.
- بعد عودة الحساب: افتح إعدادات المشروع ← Git وتحقق من الحالة. إن ظهر "تفرّع" فسيضع Lovable عمله في فرع lovable-sync؛ ادمجه في الفرع الرئيسي على GitHub قبل أي دفع جديد. إن لم يعد الربط، فإعادة الربط تنشئ مستودعًا جديدًا (لا يمكن ربط القديم).
- تنبيه: إن دُفع إلى main مباشرة بعد التفرّع، قد يستبدل نسخة Lovable، فادمج أولًا.

## 5) ما يحتاج انتباهًا الآن
- ليس هناك خطر فوري على البيانات بحسب ما أعرف.
- اختلاف الكود عن القاعدة: إن كان الكود الحالي يعتمد على شيء من الترحيلات التسعة، فقد تفشل بعض الشاشات. لم أتحقق من ذلك.
- إصلاح الأمان غير موجود في GitHub: لو أعاد أحد بناء القاعدة من ملفات GitHub فقط، ستعود الثغرة. يجب إضافة ملفه لاحقًا.
- لا تستعِد أي نسخة احتياطية دون تصدير أولًا، لأن ذلك يلغي إصلاح الأمان وأي بيانات جديدة.
- مستحسن الآن (لا يغيّر القاعدة): خذ تصديرًا من قاعدة البيانات ← الإعدادات ← تصدير البيانات.
