## 3. النتائج المطلوب التحقق منها مستقلًا

1. **الحسابات المالية:** الإقفال في سيناريو T2 أعطى مبيعات 300، وتحصيل 190، ومصروفات 5، وربح 114، وديون 60، وعهدة 0،
   والمخزون 8 و9. **أعد حساب التوقع بنفسك قبل النظر إلى النتيجة.**
2. **الحساب الموقوف أو المحذوف أو المغلق:** هل يوجد أي مسار (دالة أو جدول أو View) يتجاوز الحارس؟ الاختبار غطى
   12 دالة و22 جدولًا فقط.
3. **حدث Webhook المتأخر:** ينتهي بحالة `stale`، ويعيد إسقاط الحالة المخزنة الأحدث. هل يوجد ترتيب أحداث يكسر ذلك؟
4. **الصلاحيات:** الأعمدة التي يملك `authenticated` كتابتها في `tenants` هي `id` و`name` و`owner_user_id` و`created_at` و`updated_at`
   و`timezone` و`business_type`. تغيير `owner_user_id` مرفوض بسياسة RLS. **راجع: هل منح `UPDATE(id)` مقبول؟**
5. **ثغرة البريد:** كانت قائمة في الإنتاج. أدلة عدم الاستغلال:
   - `pgmq.metrics_all.total_messages` = 0 للطوابير الأربعة؛
   - تسلسلات `msg_id` لم تُستخدم قط (`last_value = NULL`)؛
   - الأرشيف فارغ.

   راجع كفاية هذا الدليل.
6. **التراجع:** اختبار المعاملة الملغاة طابق الإنتاج الحالي: md5 في 33/33 دالة، وACL في 35/35، و59 سياسة،
   وغياب `monjez_private`، وTRUNCATE لـ`authenticated` على 21 جدولًا وصفر لـ`anon`.

## 4. فجوات معروفة (لا تُعدّ مغلقة)

- لا نسخة احتياطية مثبتة للإنتاج ولا استعادة مجرّبة. توثيق Lovable يذكر Cloud → Database → Backups، بنسخة يومية
  محفوظة نحو 14 يومًا، ولا استعادة إلى لحظة محددة، والنسخ لا تشمل Storage. **لم يُتحقق منها بعد على المشروع.**
- **لم يُختبر التزامن الحقيقي.** كل الاختبارات في جلسة واحدة. `dblink` غير مثبت ويحتاج كلمة مرور.
- لا CI ولا اختبارات متصفح، لأن GitHub معلّق.
- لم يُتحقق من سجلات Paddle، ولا دليل على وجود أحداث أصلًا. لكل المتاجر الثمانية: trialing، وبلا اشتراك، وانتهت الفترة التجريبية.
- الافتراضات الافتراضية في Supabase تمنح `authenticated` صلاحية EXECUTE على كل دالة جديدة في `public`، فهذه مخاطرة
  نظامية. `email_queue_wake()` ما زالت ممنوحة لـ`authenticated`، وهي دالة مشغّل لا تُستدعى مباشرة.
- **سلوك قائم قبل التحديثات:** الإقفال يحسب الطلب المرتجع ضمن المبيعات. يحتاج قرار منتج.
- فروق الإصدار بين المختبر والإنتاج: PostgreSQL 17.11 مقابل 17.6، وpg_net 0.20.4 مقابل 0.20.3.
