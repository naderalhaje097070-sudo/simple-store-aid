## Concrete before/after

Current verified API: `collect_order_debt(p_order_id uuid, p_amount numeric, p_method payment_method)`. It increments paid and inserts a debt_collection payment for each accepted call. It cannot identify whether two identical20requests are one intended payment with a lost response or two genuinely distinct20payments.

Proposed API, for explicit owner authorization:
`collect_order_debt_idempotent(p_idempotency_key uuid, p_order_id uuid, p_amount numeric, p_method payment_method) returns jsonb`.

The same UUID + same actor/tenant/order/amount/method returns the original successful result and creates one stored effect, including concurrent requests and reload/lost reply. A different payload under the same key fails. A genuine second payment, even with the same20amount, receives a new UUID and may post independently within the existing remaining-balance limit.
