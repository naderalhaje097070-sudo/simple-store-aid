# Security impact
Issuer is derived only from an explicit deployment configuration after existing URL, project, alias, public-key and approved-target checks. No Host/JWT/request derivation or cloud fallback. JWKS is pinned to that validated issuer, avoiding discovery ambiguity. SDK0.20.1 retains signature, issuer, audience and default OAuth client-claim enforcement. HTTPS remote / HTTP loopback restrictions remain. The local server blocks every other fetch origin and follows no redirects. A 5xx, timeout, discovery failure, or empty finance list never proves explicit account denial. The current tools may expose RLS empty lists after ban; preserve that as a failed acceptance criterion rather than expanding this issuer-only patch into authorization policy.
