## 1. تصحيح: `INVALID_ARGUMENT` رمز عام لا يعني الرفض
- **ما كتبتُه سابقًا** في §18 و§18.1 من `C6_REVIEW_FIXES.md`، وفي تعليقَي #97 ‏`7015454022` و`7016302779`:
  - عاملتُ `{"error_code":"INVALID_ARGUMENT"}` كأن الأداة رفضت الطلب **دون** خطأ PostgreSQL؛
  - واقترحتُ «الحجم مع الكتابة» سببًا.
  - **هذا غير صحيح، ويُستبدل بما يلي.**
- **ما ثبت (تسليم Codex ‏`7016334327`):** M2 وM4 وM5 (82,065 بايت لكل واحد) أعاد كل منها **قناتين معًا**:

| القناة | المحتوى |
|---|---|
| النص | `Lovable API error: 400 query_error: Failed to run sql query: ERROR:  P0001: C6_DX_INJECTED M#` |
| البنية | `{"error_code":"INVALID_ARGUMENT"}` |

  وبعد كل منها خط أساس صفر.
- **الاستنتاج:** `INVALID_ARGUMENT` هو الرمز المنظّم الذي يصاحب **أي** خطأ SQL (400 `query_error`)، **ومنه الفشل المقصود نفسه**. لا يدل على أن الطلب لم يصل إلى PostgreSQL.
- **ما رأيته من جهتي:** في D1 وM3 أظهرت لي أداتي قناة النص وحدها. لم أرَ القناة المنظّمة، فلا أستطيع القول هل صاحبها `INVALID_ARGUMENT` أم لا.
- **رد M1 الأصلي** (`fullsize_fail.sql`، بإرسال Codex):
  - المحفوظ منه في #97 (`7015396007`) هو القناة المنظّمة وحدها، ولا يوجد نصه في أي دليل في المستودع.
  - **النتيجة: غير مُتحقق** هل وصل إلى PostgreSQL وأعاد `C6_FX_FINAL_BLOCK_FAILURE`.
  - **لم يُعد تنفيذه.** الأرجح، وهو استنتاج غير مثبت، أنه وصل وتراجع كما فعلت M2 وM5.
- **ما ثبت عن الحجم الكامل عبر الأداة:**
  - كتابة اصطناعية بحجم 82,065 بايت تصل إلى فشل مقصود ثم تتراجع دون أثر (M2: كتلة واحدة؛ M5: جملة واحدة)؛
  - 82,065 بايت بعشر كتل دون كتابة (M4) تصل إلى PostgreSQL.
- **ما لم يثبت بعد:** **اعتماد** (COMMIT) كتابة بالحجم الكامل عبر الأداة.
