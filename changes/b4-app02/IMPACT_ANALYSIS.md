# B4 / APP-02 impact analysis

Current route verifies signature, then performs independent Supabase writes without checking error/affected rows and acknowledges200. Existing tenant cache UPDATE ignores environment. New route separates verification/payload errors from retryable persistence failure and makes one service-only RPC; new private ledger + subscription + live tenant cache commit atomically. SQLSTATE permission/errors/zero affected rows/malformed RPC result cannot become success. No async in-memory queue or unimplemented durable worker.

New function SECURITY INVOKER with exact service_role execution and private least privileges; default PUBLIC/anon/authenticated EXECUTE revoked. Row/stream locks and event receipt make retries idempotent even if commit response is lost. Explicit same-time conflicting state is503, never ordered by lexical eventID. Keep current global unique provider ID; cross-env collision rejected without mutation, rather than silently reassigning a row.

Binding is explicit and private: created alone may replace a non-null pointer, ordered by immutable provider subscription.createdAt, not arbitrary event time across streams. Updated/canceled non-current streams persist with a non_current receipt without cache rebinding. Empty cache may bootstrap from a complete snapshot. Late created can bind the newest already-stored state even when its own subscription snapshot is stale. Equal creation times across different IDs fail before a new row is inserted, including bootstrap paths. New subscription created_at stores verified provider entity creation time so existing UI order is independent of delivery arrival; old rows are never rewritten. Legacy unknown binding time uses a documented conservative server floor and requires reconciliation when ambiguous.
