The initial unmodified Supabase CLI init/generation action was rejected by automatic approval review because it attempted PostHog analytics. The action was not repeated unchanged. The pinned2.101.0official source was inspected: Go internal/telemetry/state.go Disabled and service.go canSend both honor DO_NOT_TRACK=1/SUPABASE_TELEMETRY_DISABLED=1. The telemetry status command reads storedEnabled, so it initially displayed enabled despite runtime opt-out; this is not evidence of a new allowed analytics event. Native process packet tracing was unavailable locally (unshare denied), so no unobserved network-zero proof is invented.

A task-private SUPABASE_HOME with enabled:false/consent:denied and both opt-out variables was then used.
