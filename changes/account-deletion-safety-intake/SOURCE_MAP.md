There is no anonymization/retention policy inference. The business reference FKs are single-column IDs, not tenant-composite FKs; inconsistent cross-tenant references, if present, can widen SET NULL/CASCADE effects beyond rows bearing the deleted tenant_id. No such live data is assumed. security_scan_runs has triggered_by text, findings references only runs; deleting a user/tenant does not automatically remove these tables or queue payloads.
